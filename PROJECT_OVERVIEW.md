# Swahit: The Full Technical & Product Blueprint

This document provides an exhaustive, 360-degree technical and strategic overview of the **Swahit** Mental Wellness Platform. It covers everything from high-level business logic to granular database schemas and API specifications.

---

## 🏗️ 1. Project Vision & Goals
Swahit is built to bridge the gap between AI-driven self-help and professional clinical therapy.
- **Empathetic AI:** Using LLMs to provide immediate, non-judgmental emotional support.
- **Data-Driven Insights:** Transforming daily mood logs into long-term wellness trends.
- **Professional Escalation:** Intelligently guiding users toward human experts when clinical needs are detected.
- **Scalable Entitlement:** A dynamic subscription engine that allows for rapid pricing and feature pivots.

## 🧠 4. Deep-Dive: AI & Memory Logic

### The Swahit Companion
The chatbot is not a standard prompt-response loop. It implements a **stateful memory engine**:

1. **Context Loading:** On every message, the `ChatbotService` loads the `UserMemoryProfile`.
2. **System Prompt Augmentation:** The AI is fed a dense context block including:
   - User's preferred name.
   - Long-term stressors identified in previous sessions.
   - Positive habits the user is trying to build.
   - Summaries of the last 50 messages.
3. **Distress Detection (Passive Scan):** Every message is scanned for `DISTRESS_KEYWORDS`.
   - *Logic:* `DISTRESS_KEYWORDS.some(k => userContent.includes(k))`
   - *Action:* If true, `suggestProfessional` flag is returned to the frontend.
4. **Memory Sync (Asynchronous Background Task):**
   - Every 15 messages, a background worker triggers.
   - It sends the conversation log to a smaller Gemini Flash instance.
   - It extracts key emotional themes and updates the `UserMemoryProfile`.
   - This ensures the AI "remembers" the user without bloating the context window.

## 📊 5. Database Schema: Full Specification

### 👥 User & Identity
- **`User` Table:** 
  - `id`, `email`, `password`, `name`, `role` (USER/ADMIN/DOCTOR).
  - `legalConsentAt`: Tracks when terms were accepted.
- **`UserMemoryProfile` Table:**
  - `preferredName`, `recurringStressors`, `goals`, `emotionalPatterns`.
  - `distressCount`: Counter for clinical assessment.

### 📝 Chat & Interactions
- **`ChatSession`**: `id`, `userId`, `title`, `updatedAt`.
- **`ChatMessage`**: `id`, `sessionId`, `role` (user/ai), `content`, `emotionTag`.
- **`ChatSummary`**: Historical summaries generated by background sync.

### 🏥 Clinical System
- **`Doctor`**: `name`, `specialty`, `consultFee`, `rating`, `languages`.
- **`DoctorSlot`**: `doctorId`, `startTime`, `endTime`, `isBooked`.
- **`Appointment`**: `userId`, `doctorId`, `status` (PENDING/CONFIRMED/CANCELLED), `sessionType` (VIDEO/AUDIO/CHAT).

### 📈 Wellness Tracking
- **`MoodEntry`**: `userId`, `mood` (HAPPY/CALM/SAD/etc), `intensity` (1-10), `date` (unique per user/day).
- **`QuestionnaireResult`**: `userId`, `score`, `answers` (JSON), `feedback`.

### 💎 Subscription & Entitlements (Modern v2)
- **`Plan`**: `name` (FREE/SILVER/GOLD/PLATINUM), `priceMonthly`, `priceYearly`.
- **`Feature`**: `key` (e.g., `ai_chat_advanced`), `category` (AI/ANALYTICS/etc).
- **`PlanFeature`**: Entitlement junction table with `limitValue`.
- **`UserSubscription`**: Tracks specific users on specific plans.
- **`FeatureUsage`**: Tracks daily/monthly consumption for rate limiting.

## 📡 6. API Endpoint Inventory

### Authentication
- `POST /auth/register` (DTO: `RegisterDto`) -> Returns success.
- `POST /auth/login` (DTO: `LoginDto`) -> Returns `{ access_token, user }`.

### Chatbot
- `GET /chatbot/threads` -> Returns list of chat sessions.
- `GET /chatbot/thread/:id` -> Returns full message history.
- `POST /chatbot/message` -> Returns `{ session, message, suggestProfessional }`.
- `DELETE /chatbot/thread/:id` -> Clears history.

### Mood
- `POST /mood` -> Body: `{ mood, intensity, notes }`.
- `GET /mood` -> Returns chronological history + stats.

### Appointments
- `GET /appointments/doctors` -> Optional query: `specialty`.
- `POST /appointments/book` -> Body: `{ doctorId, patientName, preferredTime }`.
- `GET /appointments/my` -> User's upcoming schedule.

## 🔒 8. Security & Performance

- **Rate Limiting:** Implemented at the DB level through the `FeatureUsage` table.
- **Validation:** Every request is filtered through a global NestJS `ValidationPipe` using `class-validator`.
- **SQL Injection Prevention:** Prisma ORM handles all query parameterization.
- **CORS:** Restricted to trusted origins (configured via `FRONTEND_URL` env).
- **Asynchronous Processing:** Memory summarization and email hooks (future) are triggered in the background to prevent UI lag.
